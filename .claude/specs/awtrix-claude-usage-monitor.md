## Overview
A .NET 10 worker service that runs on the user's Windows 11 machine, polls Anthropic's OAuth usage endpoint with the token Claude Code already stores locally, and pushes three rotating custom-app screens to a Ulanzi TC001 pixel clock (32×8 LED matrix) running AWTRIX3 firmware: 5-hour session usage %, countdown to session reset, and 7-day limit usage %. Visual target is the reference photo `C:\src\ClaudeCodeMonitor\Ulanzi.jpg`: pixel-art Clawd on the left, big percentage on the right, progress bar along the bottom row.

## Scope
### In Scope
- Long-running .NET worker, auto-started at user login, polling every 2 minutes (configurable)
- Reading the OAuth access token from `%USERPROFILE%\.claude\.credentials.json` (read-only)
- Calling the Anthropic OAuth usage endpoint for 5-hour and 7-day utilization + reset times
- Pushing/removing three AWTRIX3 custom apps over the clock's HTTP API
- Threshold coloring (green/yellow/red), grayscale stale state, app auto-expiry via AWTRIX `lifetime`
- README with build, configuration, and auto-start-at-login instructions

### Out of Scope
- AWTRIX notifications/popups (`/api/notify`) — screens only, decided explicitly
- MQTT transport — HTTP custom apps only
- Cost or token-count screens
- OAuth token refresh or any write to `~/.claude`
- Running as a Windows Service (login-scoped worker only)
- macOS/Linux support

### Deferred
- Per-model weekly limits (e.g. a separate Opus screen) if the usage endpoint exposes them
- Additional lifestyle screens (tides, weather) as in the inspiration post

## Requirements
- Poll on a fixed interval (default 2 minutes) using `PeriodicTimer` inside a `BackgroundService`; run the first poll immediately at startup, before the first timer tick
- Each poll: read `%USERPROFILE%\.claude\.credentials.json` fresh from disk with a file share mode that permits concurrent writers, extract `claudeAiOauth.accessToken` and `claudeAiOauth.expiresAt` (epoch milliseconds)
- Call `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <accessToken>` and the `anthropic-beta: oauth-2025-04-20` header; parse `five_hour` and `seven_day` objects, each carrying `utilization` (percent, 0–100) and `resets_at` (ISO 8601 timestamp)
- The endpoint is undocumented: the first implementation step is to call it once with the real token and capture the live response shape; parsing must tolerate extra fields and treat missing `five_hour`/`seven_day` values as 0% with no reset time
- Push three AWTRIX3 custom apps via `POST http://<AwtrixHost>/api/custom?name=<app>` with a JSON body; remove an app by POSTing an empty body to the same URL
  - `claude_session` — Clawd pixel art (8×8 zone, columns 0–7) rendered with `draw` commands, session utilization as right-aligned text `NN%`, `progress` = session utilization so the bottom-row bar fills as allowance is consumed
  - `claude_reset` — hourglass glyph in the icon zone, time until `five_hour.resets_at` as text `H:MM` (recomputed from `resets_at` at every poll, never counted locally); no progress bar
  - `claude_week` — calendar glyph in the icon zone, weekly utilization as text `NN%`, `progress` = weekly utilization
- Apply threshold colors to each screen's text and progress bar based on that screen's utilization (`claude_reset` uses the session utilization): green `#00C853` at 0–59%, yellow `#FFD600` at 60–84%, red `#FF1744` at 85–100%
- Clamp all utilization values to the 0–100 range before rendering
- Remove `claude_reset` from rotation (empty-body POST) whenever `five_hour.resets_at` is absent or in the past; `claude_session` and `claude_week` always remain in rotation, showing 0% when idle
- Send every app with `lifetime` = 3 × poll interval in seconds (360 at the default interval) and the lifetime mode that deletes the app on expiry, so a dead poller leaves a clean clock face
- Stale state: keep the last known values but render every element — Clawd, glyphs, text, progress bar — in grayscale (`#9E9E9E` for text/bar, dimmer grays for pixel art); enter stale immediately on missing/unparseable credentials, or HTTP 401/403; enter stale after 3 consecutive timeouts/5xx responses
- On HTTP 429, pause usage-endpoint calls for max(`Retry-After`, one poll interval), then resume normal polling; keep pushing the current (stale-marked if applicable) screens to the clock during the pause
- Failed polls perform no in-cycle retries — the next scheduled tick is the retry
- Configuration in `appsettings.json` under a `Monitor` section: `AwtrixHost` (required, no default), `PollIntervalMinutes` (default 2), `WarnThresholdPercent` (default 60), `CriticalThresholdPercent` (default 85), `StaleAfterFailures` (default 3), `CredentialsPath` (default `%USERPROFILE%\.claude\.credentials.json`)
- Validate configuration at startup and exit with a clear error message when `AwtrixHost` is missing or thresholds are not in ascending order within 0–100
- README documents: `dotnet publish` for a self-contained build, filling in `AwtrixHost`, and registering auto-start at login via a Task Scheduler logon trigger (`schtasks /Create /SC ONLOGON ...`) or a Startup-folder shortcut

## Prohibitions (Don'ts)
- NEVER write to, delete, or exclusively lock `%USERPROFILE%\.claude\.credentials.json` or anything else under `~/.claude` — an exclusive lock or corrupt write can break the running Claude Code CLI
- NEVER attempt an OAuth token refresh with the stored `refreshToken` — a refresh races Claude Code's own refresh and can invalidate the CLI's login; an expired token just means Claude Code is idle: keep showing the last snapshot in normal colours (windows past their reset time shown as 0%) until the user next uses Claude Code
- NEVER log, persist, or transmit the access token or any part of `credentials.json` anywhere except the `Authorization` header of requests to `api.anthropic.com` — nothing sensitive goes to the clock, the console, or disk
- NEVER call the usage endpoint more than once per poll cycle, and never during an active 429 pause — this is a courtesy consumer of an undocumented endpoint
- NEVER use AWTRIX `/api/notify` or any interrupting popup — the three rotating screens are the entire surface, decided explicitly
- NEVER render stale data in normal colors — stale must be unmistakably grayscale so old numbers are never trusted
- NEVER let a poll-cycle exception terminate the worker — every failure path logs and continues to the next tick; only invalid startup configuration may exit the process

## Decision Tree
```
Every poll tick (default 2 min; first tick immediately at startup):

1. Read %USERPROFILE%\.claude\.credentials.json (shared read, no lock)
   ├─ file missing or unparseable ......... -> STALE, skip to step 3
   └─ expiresAt in the past ............... -> IDLE: last snapshot, reset windows zeroed (STALE if none yet)
      (Claude Code refreshes the token next time the user runs it)
2. GET https://api.anthropic.com/api/oauth/usage (Bearer token)
   ├─ 200 ................................. -> parse 5h + 7d utilization
   │                                           and reset times; failures
   │                                           counter resets to 0
   ├─ 401 / 403 ........................... -> STALE
   ├─ 429 ................................. -> pause endpoint calls for
   │                                           max(Retry-After, 1 interval);
   │                                           continue to step 3
   └─ timeout / 5xx / network error ....... -> keep last data;
                                               STALE once consecutive
                                               failures reach 3 (~6 min)
3. Render + POST custom apps to http://<AwtrixHost>/api/custom
   ├─ claude_session: always (0% when idle)
   ├─ claude_reset: only when resets_at exists and is in the future;
   │                otherwise POST empty body to remove it
   ├─ claude_week: always
   ├─ every push carries lifetime = 3 x poll interval (delete on expiry)
   └─ clock unreachable ................... -> log Warning, retry next tick
```

## Domain Rules & Exceptions
| Rule | Applies When | Exception | Who Can Override |
|------|-------------|-----------|-----------------|
| Green text/bar at 0–59% utilization | Fresh data, per screen | Stale → grayscale `#9E9E9E` | Thresholds configurable in `Monitor` section |
| Yellow at 60–84%, red at 85–100% | Fresh data, per screen | Stale → grayscale | Thresholds configurable |
| `claude_reset` colored by session utilization | Countdown visible | Stale → grayscale | No override |
| Countdown hidden | `five_hour.resets_at` absent or in the past | None | No override |
| Stale after 3 consecutive transient failures | Timeouts, 5xx, network errors | 401/403, expired token, bad credentials file → stale immediately | `StaleAfterFailures` configurable |
| App `lifetime` = 3 × poll interval (360 s default), delete on expiry | Every app push | None | Follows `PollIntervalMinutes` |
| 429 pauses endpoint calls for max(Retry-After, 1 interval) | HTTP 429 received | Missing Retry-After header → 1 interval | No override |
| Utilization clamped to 0–100 before render | Every render | None | No override |

## Escalation & Guardrails
- **Fail if** (startup only, process exits with a clear console error): `AwtrixHost` missing, or thresholds not satisfying 0 < warn < critical ≤ 100
- **Queue for review if** (stale-marked on the clock, worker keeps running): credentials missing/unparseable, token expired, HTTP 401/403, or 3 consecutive transient failures
- **Retry/degrade if**: transient endpoint failure → wait for next tick; HTTP 429 → pause endpoint calls for max(Retry-After, one interval); clock unreachable → log Warning, retry next tick
- **Alert if**: never — no popups, no notifications (explicit decision)

## Data Model
No database. Two immutable in-memory records:

- **UsageSnapshot** — `SessionUtilization` (int, 0–100), `SessionResetsAt` (nullable DateTimeOffset), `WeeklyUtilization` (int, 0–100), `WeeklyResetsAt` (nullable DateTimeOffset), `RetrievedAt` (DateTimeOffset)
- **DisplayState** — `LastSnapshot` (nullable UsageSnapshot), `IsStale` (bool), `ConsecutiveFailures` (int), `PausedUntil` (nullable DateTimeOffset, set by 429 handling)

`DisplayState` lives in the worker; a fresh `UsageSnapshot` replaces the previous one only on HTTP 200.

## API Contract (if applicable)
No inbound API — the worker exposes nothing. Outbound contracts:

**Anthropic usage endpoint (undocumented; verify live shape before relying on it)**
- Route: `GET https://api.anthropic.com/api/oauth/usage`
- Auth: `Authorization: Bearer <accessToken from credentials.json>`, header `anthropic-beta: oauth-2025-04-20`
- Success response: 200 with JSON containing `five_hour` and `seven_day` objects, each with `utilization` (number, percent) and `resets_at` (ISO 8601); unknown extra fields must be ignored
- Error responses: 401/403 → token invalid/expired → stale; 429 → pause per Retry-After; 5xx → transient failure

**AWTRIX3 custom app API (Ulanzi TC001 on the LAN)**
- Route: `POST http://<AwtrixHost>/api/custom?name={claude_session|claude_reset|claude_week}`
- Auth: none (LAN device)
- Request body fields used: `draw` (pixel-art commands for the left 8×8 zone), `text` (string), `color` (hex string), `progress` (int 0–100), `progressC` (hex, bar color), `lifetime` (int seconds), lifetime mode field set to delete-on-expiry; empty JSON body removes the app
- Success response: 200 → app stored/updated in rotation
- Error responses: any non-200 or connection failure → log Warning, retry next tick

## Acceptance Criteria
### Happy Path
- [ ] Given valid credentials and a reachable endpoint reporting 42% session / 12% weekly, when a poll tick runs, then `claude_session` shows "42%" in green with the bottom bar 42% filled, `claude_week` shows "12%" in green with the bar 12% filled, and both carry `lifetime` 360
- [ ] Given `five_hour.resets_at` is 1 h 23 m in the future, when the poll renders, then `claude_reset` shows "1:23" colored by the session threshold color
- [ ] Given session utilization 72%, then `claude_session` text and bar are yellow `#FFD600`; given 91%, they are red `#FF1744`
- [ ] Given the worker starts, then the first poll and clock push complete immediately without waiting for the first 2-minute tick
- [ ] Given Claude Code is idle (no active window, `resets_at` absent), then `claude_session` shows "0%" green with an empty bar, `claude_week` shows current weekly %, and `claude_reset` is removed via an empty-body POST

### Negative / Prohibition Tests
- [ ] Given any number of poll cycles, then `credentials.json` is opened read-only with shared access and its content and timestamps are never modified
- [ ] Given an expired token (`expiresAt` in the past), when a poll runs, then no request is made with the `refreshToken`, no refresh endpoint is called, and the screens render grayscale
- [ ] Given verbose logging, then no log line and no AWTRIX request body ever contains the access token, refresh token, or raw credentials JSON
- [ ] Given HTTP 429 with `Retry-After: 600`, then no usage-endpoint call occurs for 600 seconds, while clock pushes continue
- [ ] Given all failure modes, then no request to `/api/notify` is ever issued
- [ ] Given stale state, then no element renders in green, yellow, or red — grayscale only
- [ ] Given the usage endpoint throws or the clock connection is refused, then the worker process stays alive and the next tick runs on schedule

### Edge Cases
- [ ] Given the endpoint returns utilization 104 or −3, then the rendered value is clamped to 100 or 0
- [ ] Given the endpoint response lacks `seven_day`, then `claude_week` shows "0%" and the poll is otherwise treated as successful
- [ ] Given the machine wakes from sleep, then the next tick polls normally and the countdown, being recomputed from `resets_at`, is immediately correct
- [ ] Given session utilization is exactly 60 or 85, then the color is yellow (60) and red (85) — thresholds are inclusive lower bounds
- [ ] Given `resets_at` passed while the worker was asleep, then `claude_reset` is removed on the next tick

### Integration / Resilience
- [ ] Given 3 consecutive endpoint timeouts, then screens switch to grayscale while still showing the last known values
- [ ] Given the clock is unplugged, then each tick logs one Warning and the worker continues; when the clock returns, the next tick repopulates all apps without restart
- [ ] Given the worker is killed, then within 3 × poll interval the clock drops all three apps and returns to its normal rotation
- [ ] Given credentials become readable again after being missing, then the next tick returns to colored rendering with fresh data

## Key Decisions Made
| Decision | Options Considered | Chosen | Rationale |
|----------|-------------------|--------|-----------|
| Runtime | Node.js, Python, .NET/C# | .NET 10 / C# | User preference; SDK 10.0.100 installed; matches KitchenDashboard conventions |
| Usage data source | OAuth usage endpoint, local JSONL transcripts, both | OAuth usage endpoint | Exact utilization + reset times, no estimation; token already on disk |
| Clock transport | HTTP custom apps, MQTT | HTTP custom apps | No broker needed; apps join normal rotation |
| Screens | session %, countdown, weekly %, cost/tokens | session % + countdown + weekly % | Cost screen declined |
| Number semantics | % remaining, % used | % used | User choice; 0% when idle, bar fills with consumption |
| Colors | thresholds, static | Green/yellow/red at 60/85 | Glanceable across the room |
| Idle behavior | keep showing, remove apps, minimal screen | Keep showing 0% (countdown hidden) | Confirms poller liveness; countdown meaningless without a window |
| Hosting | worker at login, Windows Service, scheduled console | Worker at login | Simple to run/debug; usage only matters while logged in |
| Stale look | gray last value, question mark, expire apps | Gray last value | Retains last reading, unmistakably stale |
| Dead-poller cleanup | AWTRIX lifetime delete, apps persist | lifetime = 3 × interval, delete | Clock never shows frozen data from a dead process |
| Retry strategy | skip to next tick, exponential backoff | Skip to next tick (+ Retry-After on 429) | 2-minute cadence already gentle; less code |
| Alerts | none, one-shot, alert + reset | None | Red screens are enough |
| Observability | console only, console + file | Console only | Single-user tool; run in a terminal to diagnose |
| Conventions file | AGENTS.md + thin CLAUDE.md, CLAUDE.md only, skip | AGENTS.md + thin CLAUDE.md | Vendor-agnostic |
